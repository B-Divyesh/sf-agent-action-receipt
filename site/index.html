How it works

Write evidence around the tool call

  1. 01

    Prepare the action

    Hash the authority and arguments before the tool can change real state.

  2. 02

    Run the tool

    Call existing tool code while the ledger keeps one action order.

  3. 03

    Record the outcome

    Append a signed result or save explicit unresolved evidence for recovery.

Failure recovery

Keep post-action failures visible

The ledger signs an unresolved fallback before execution. It can still record the action if later hashing or signing fails.

Prepared receipt→Tool call→Final receipt or outbox

Install

Add receipts to a TypeScript agent

Supply an Ed25519 signer and a durable receipt store for restart recovery.

npm install @sociobot/agent-action-receipt

const ledger = createReceiptLedger({ signer, actor, store });
const action = await ledger.execute({
  tool, authority, args, run
});

verifyBundle(ledger.exportBundle());

Limits and privacy

Know what the receipt proves

  • One ledger has one order. Separate processes do not gain a shared global order.
  • Remote actions are not exactly once. Tool state and receipt storage remain separate systems.
  • The signing key makes the claim. Add an external witness when independent evidence is required.
  • You control storage. The package has no hosted account, telemetry, or private-key store.
